# Calculator evaluation storage

## TL;DR

`CalculatorEvaluationRecord` validates host context and contiguous ordered output
identity. `PostgresCalculatorEvaluationStore` appends one immutable terminal
envelope. Inputs, outcome and all outputs become visible atomically, including a
complete evaluation with zero outputs. This does not run calculators or schedule work.

## Evidence and retries

The replay key includes tenant scope, exact registered release, configuration
identity, finalized window, knowledge cutoff and canonical ordered input references.
Processing time is stored separately and retained from the first attempt. The
unique replay-key digest prevents two evaluation IDs claiming the same key;
conflicts compare full key, processing time, outcome and ordered outputs. A hash
collision is a conflict, never an assumption of equivalent content.

For this PostgreSQL adapter, opaque semantic evidence IDs are lowercase hexadecimal
SHA-256 of the JSON tuple generated by `analytics.semantic_evidence_id`: tenant,
message, package, version, output index, binding, integral revision text and time
basis. The indexed function is a versioned storage encoding: future changes need
a new encoding, not replacement of old identities. A digest is not authorization.
The database verifies the actual immutable history/binding, scope, registered input
property, event time and first resolution cutoff. The runner must still establish
selection completeness from one consistent snapshot; resolution time is existing
semantic evidence, not a claim of physical insertion time. Configuration IDs pin the registered release, window span, allowed lateness and
minimum-sample count in an immutable snapshot. Administration/activation stays PR7.
The append transaction rolls back snapshot pins on conflicting evaluation IDs.

Derived target references commit with the envelope and prevent asset deletion
from orphaning calculated evidence.

Output position supplies the existing ADR 0007 output index. The database checks
target tenant, type membership, exact registered property, decimal value and unit.
The current registered mean ABI only accepts decimal outputs. Decimal strings
are normalized without floating-point conversion and limited to 4096 bytes.
Terminal failures and insufficient evidence cannot publish partial outputs.

## Rollout and verification

Apply migration 0039 before any store consumer. It adds immutable envelopes, configuration pins and derived output-target foreign
keys, plus an
expression index on history. Index creation is transactional and can block history
writes; measure its build against retained history before deployment and use an
approved idle window. No history data is rewritten or reinterpreted. Keep the
additive schema and immutable facts on code rollback. Future read APIs are PR8;
current-property/SSE integration is intentionally separate.

Run `cargo test -p fleetiq-postgres --test calculator_evaluations --locked` against
migrated PostgreSQL 18.6, followed by the applicable contributor acceptance gate.
